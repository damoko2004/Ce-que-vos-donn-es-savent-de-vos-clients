La thèse

Le modèle n’a jamais été le problème

Les bibliothèques sont gratuites et la documentation abondante : un modèle correct s’entraîne en une après-midi. Ce qui bloque se situe avant et après. Avant, parce que personne n’a formulé la décision que le modèle est censé améliorer. Après, parce que le score arrive dans un tableau que personne ne sait utiliser, et que nul ne peut dire six mois plus tard si l’opération a rapporté quelque chose.

AVANT

Formuler

Traduire une préoccupation commerciale en problème soluble : une décision, un horizon, une cible, une contrainte de capacité.

PENDANT

Construire

La donnée datée, le modèle, l’évaluation — et le seuil qui découle du coût d’une erreur, jamais d’une valeur par défaut.

APRÈS

Prouver

Le groupe témoin, l’effet incrémental, la conversion en euros. Y compris quand le résultat est négatif.

Exécuter le livre

Chaque bloc tourne, et le dépôt fournit ce qu’il faut pour cela

Un livre technique dont le code ne s’exécute pas est un livre qu’on ne peut pas vérifier. Le dépôt contient donc trois choses au-delà du code lui-même : les jeux de données, un socle qui fournit les objets décrits mais non reproduits dans le texte, et une chaîne de tests qui rejoue tout à chaque modification.

SOCLE.PY

Les objets que le texte décrit

Une matrice d’interactions, un corpus déjà indexé, un service de langue : le livre les décrit sans les reproduire. Le socle en donne une implémentation minimale, pour que chaque bloc s’exécute.

DATA/

Tous les jeux, versionnés

Panel télécom, freemium, verbatims, catalogue et images, accords fournisseurs, enquête et sa vérité de terrain, corpus et jeux d’évaluation, journaux de gouvernance.

TESTS/

Vérifiable en une commande

pytest tests/ -q contrôle que les 80 000 clients, les cinq segments RFM et les trois axes de l’ACP sortent bien aux valeurs imprimées.

Ce qui n’a pas pu être exécuté, et pourquoi

Six blocs n’ont pas tourné sur la machine de test : deux téléchargent un modèle pré-entraîné, quatre dépendent de duckdb, quanteda, leaflet ou srvyr, indisponibles dans cet environnement. Ils fonctionnent sur un poste connecté disposant de ces paquets. Le dépôt le dit plutôt que d’afficher un taux de réussite que la mesure n’établit pas — c’est exactement ce que le chapitre 25 du livre reproche aux tableaux de bord flatteurs.

Données synthétiques, et pourquoi

Tous ces jeux sont générés. Aucune donnée réelle d’entreprise ou de personne n’est diffusée ici, et le livre le dit explicitement. Les jeux sont construits pour porter les structures qu’ils doivent enseigner — corrélations latentes, biais de sélection, anomalies connues — et non pour imiter une base particulière.

Prise en main

Quelques commandes, et vous reproduisez les chiffres du livre

Ces commandes ne téléchargent pas l’ouvrage : elles régénèrent ses jeux de données et vérifient que les résultats publiés sortent bien aux valeurs imprimées. Le texte du livre n’est pas diffusé dans ce dépôt. 

git clone https://github.com/damoko2004/Ce-que-vos-donn-es-savent-de-vos-clients.git
cd Ce-que-vos-donn-es-savent-de-vos-clients
pip install -r requirements.txt
python data/generer.py
pytest tests/ -q

Le générateur affiche ses contrôles. Vous devez lire exactement ceci :

Pour la partie R, depuis la racine du dépôt : 

Rscript r/installer.R
Rscript r/chapitre_07/R-C07-02_equivalent_memes_seuils.R
Ordre de lecture du code

Les blocs d’un même chapitre se lisent dans l’ordre de leur rang : PY-C08-01 avant PY-C08-02. Certains réutilisent les objets créés par le précédent, exactement comme dans un carnet de notes. Les en-têtes de fichier rappellent le chapitre d’origine.
